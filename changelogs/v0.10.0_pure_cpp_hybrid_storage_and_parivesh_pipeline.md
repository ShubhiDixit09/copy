# Changelog: v0.10.0 - Pure C++ Hybrid Storage & PARIVESH Ingestion Pipeline

**Release Date:** 2026-09-08  
**Scope:** SIH 26016 Phase-1 Vertical Slice, Pure C++ Ingestion, Google Drive Vault, Neon DB 4-Layer Relational Control Plane, 7-Rule Evidence Engine, Change Detection.

---

## 1. Architectural Overview & Context
In accordance with the project's non-negotiable **C++ First** mandate and the ₹0-friendly Hybrid Cloud blueprint:
- **Neon Serverless PostgreSQL (with PostGIS)**: Serves as the searchable, relational control plane database storing metadata, 4-tier schemas (Sources, Source Records, Snapshots, Artifacts & Canonical Events), PostGIS parcel geometries, and state projections. Large binary files and raw responses are strictly excluded from Neon.
- **Google Drive Webhook Vault**: Serves as the immutable object store. Ingested payloads (JSON, HTML, PDFs) are partitioned by date (`DHARTI_EVIDENCE_VAULT/raw/{source}/{YYYY}/{MM}/{DD}/snapshot_XXX.json`) and never overwritten, preserving bitemporal provenance.
- **Pure C++17 Core Pipeline**: Eliminates external Python collector daemons, executing the entire vertical slice natively in C++.

## 2. New Pure C++ Components Added

### A. Cryptographic Security (`include/dharti/utils/sha256.hpp`)
- Implemented pure C++17 RFC 6234 compliant SHA-256 cryptographic hasher with zero external library dependencies.
- Verified against NIST and RFC 6234 standard test vectors.

### B. Evidence Domain Models (`include/dharti/models/evidence.hpp`)
- `Source`: Registry of external authoritative and mock systems with polling intervals.
- `SourceHealth`: Live observability metrics including current lag seconds, success/attempt timestamps, consecutive failure counters, and SLA status (`HEALTHY`, `DEGRADED`, `OFFLINE`).
- `SourceRecord`: Stable external entity identities (e.g. `IA/KA/NHA/10482/2026`).
- `SourceSnapshot`: Immutable pointers linking source records to Google Drive file IDs, SHA-256 checksums, and parser/schema versioning.
- `EvidenceArtifact`: Bridge entity between Google Drive vault files and Neon DB status (`PENDING`, `ACCEPTED`, `QUARANTINED`, `REJECTED`).
- `CanonicalEvent`: Bitemporal workflow event envelope with correlation IDs, payloads, and evidence references.
- `EvidenceException`: Trapped contradictions and circuit breaker quarantine incidents.

### C. MoEFCC PARIVESH Clearance Adapter (`include/dharti/adapters/parivesh_adapter.hpp`, `src/adapters/parivesh_adapter.cpp`)
- Implements `IAdapter` for Forest Clearance (FC), Environmental Clearance (EC), and Wildlife Clearance (WC).
- Normalizes raw application proposals, extracts proposal numbers, clearance categories, diversion areas (Ha), tree felling quotas, and issuing conditions.
- Serializes canonical JSON and computes SHA-256 digest.

### D. 7-Rule Deterministic Evidence Gate & Change Detector (`include/dharti/services/evidence_engine.hpp`, `src/services/evidence_engine.cpp`)
- **Rule 1 — Trusted Authority**: Verifies source authority equals `GOVERNMENT` or authenticated `MOCK`.
- **Rule 2 — Stable Source Record ID**: Validates file/proposal identifier format.
- **Rule 3 — Valid Schema Conformance**: Enforces presence of mandatory clearance attributes.
- **Rule 4 — Cryptographic Hash Integrity**: Verifies SHA-256 presence and correctness.
- **Rule 5 — Impossible Jump Detection**: Traps anomalies (e.g., area jump $> 1000\%$ or negative area) into `QUARANTINED`.
- **Rule 6 — Identity Conflict Detection**: Validates hierarchical partition formatting.
- **Rule 7 — Cross-Source Contradiction**: Validates consistency against active corridor scope.
- **Change Detector**: Evaluates consecutive snapshots, detects field mutations (`UNDER_PROCESS` -> `APPROVED`), and emits canonical events linking old and new Drive snapshot IDs.

### E. Google Drive Vault Client in C++ (`include/dharti/storage/gdrive_client.hpp`, `src/storage/gdrive_client.cpp`)
- Connects directly to Google Apps Script Webhook (`https://script.google.com/macros/s/AKfycbwdFuqoOa06F0Z1wIFJ6Awlkr_EM5ex-PJBjKPLV7U-Xa5Uyqwbw4nphvUmFU2Wi-P6mA/exec`).
- Base64 encodes payloads and archives snapshots into structured date folders (`DHARTI_EVIDENCE_VAULT/raw/parivesh/2026/09/08/`).
- Returns machine pointer `file_id` and browser link `web_link`.

### F. Neon PostgreSQL Control Plane Client (`include/dharti/storage/neon_client.hpp`, `src/storage/neon_client.cpp`)
- Pure C++ client managing 4 layers in Neon Serverless PostgreSQL:
  - Upserts source records and registers health metrics.
  - Inserts immutable snapshot pointers and evidence artifacts.
  - Appends canonical workflow events.
  - Records quarantined incidents into `exceptions` table.
